# Kronos 采样参数详解

## Temperature (T)

### 定义

Temperature（温度）是 Kronos 自回归采样过程中的核心参数，控制模型从概率分布中选取下一个 token 时的**随机性程度**。

### 源码机制

采样流程位于 `model/kronos.py` 的 `sample_from_logits` 函数（L373-386）：

```
logits → logits / T → top_k/top_p 过滤 → softmax → multinomial 采样
```

关键一步是 `logits = logits / temperature`，它直接缩放 logits 值，再送入 softmax 转为概率分布。

### 工作原理

Temperature 通过缩放 logits 来调节 softmax 输出的概率分布形状：

| T 值 | logits 缩放 | softmax 后概率分布 | 效果 |
|------|-----------|------------------|------|
| T → 0 | logits / 0.01 → 极大 | 接近 one-hot（几乎100%给最高概率项） | 贪心选择：总是选概率最高的 token |
| T = 0.01 | logits 放大100倍 | 非常尖锐 | 几乎确定性，结果稳定 |
| T = 1.0 | logits 不变 | 原始模型分布 | 标准采样：忠实反映模型学到的分布 |
| T = 2.0 | logits 缩小一半 | 非常平坦 | 更随机：低概率 token 也有机会被选中 |

**直觉理解**：可以把 T 想象为"选择面的宽窄"。T 越低，选择越集中于最高概率项；T 越高，选择越分散到低概率项。

### 实测数据

测试条件：SH600519（茅台），lookback=400，pred_len=20，最后一日收盘价 7948.18

| T | close 标准差 | 末值 | 涨跌幅 | 解读 |
|---|------------|------|--------|------|
| 0.01 | 203.32 | 8734.49 | +9.89% | 几乎贪心，结果最稳定 |
| 0.1 | 216.64 | 8754.62 | +10.15% | 接近贪心，微小随机性 |
| 0.5 | 182.93 | 8712.55 | +9.62% | 轻度随机 |
| **1.0** | **175.55** | **8644.33** | **+8.76%** | **标准采样，忠实模型分布** |
| 1.5 | 171.62 | 8496.25 | +6.90% | 增加随机性，路径更发散 |
| 2.0 | 201.96 | 8456.30 | +6.39% | 高随机性，路径波动更大 |

### 修改 T 会影响什么

1. **预测稳定性**：T 越低，同一输入多次预测结果越一致；T 越高，每次预测路径差异越大
2. **预测质量**：T=1.0 是模型训练时的匹配温度，理论上是最优的；T 过低可能错过合理的低概率路径（过度自信），T 过高会产生不合理的预测（过度随机）
3. **涨跌停边界**：T 越高，预测路径越可能触及涨跌停边界（±10%），因为随机性增大了极端路径的概率
4. **与 sample_count 的配合**：
   - `sample_count=1, T=0.01`：确定性预测，适合回测
   - `sample_count=10, T=1.0`：概率预测，多条路径取均值，适合风险评估

### T=0.0 的问题

当 T=0 时，`logits / 0 = inf`，softmax 后概率分布变为 `[nan, nan, ...]`，`torch.multinomial` 无法从 NaN 概率中采样，会报错：

```
RuntimeError: probability tensor contains either inf, nan or element < 0
```

这是模型代码中缺少 T=0 特殊处理（应走 argmax 路径）的问题。

**替代方案**：使用 `T=0.01` 即可达到几乎等价于贪心搜索的效果，且不会触发错误。

## top_p（核采样阈值）

### 定义

top_p（nucleus sampling）控制采样时保留的 token 累积概率上限。只从累积概率达到 top_p 的最小 token 集合中采样。

### 工作原理

1. 将所有 token 按概率从高到低排序
2. 计算累积概率
3. 移除累积概率超过 top_p 的 token
4. 从剩余 token 中重新归一化并采样

| top_p | 效果 |
|-------|------|
| 1.0 | 不过滤，从全部词表中采样 |
| 0.9 | 保留累积概率前90%的 token，过滤掉尾部低概率项 |
| 0.5 | 仅保留累积概率前50%的 token，大幅缩小选择范围 |

### 推荐值

- **0.9**（默认）：平衡多样性和合理性，适合大多数场景
- **0.5**：更保守，适合追求稳定性的场景
- **1.0**：不过滤，完全依赖 Temperature 控制随机性

## top_k（Top-k 过滤）

### 定义

top_k 限制采样时只考虑概率最高的 k 个 token。

| top_k | 效果 |
|-------|------|
| 0 | 不启用（默认） |
| 10 | 只从概率最高的10个 token 中采样 |
| 50 | 只从概率最高的50个 token 中采样 |

### 与 top_p 的关系

- top_k 是硬性数量限制，top_p 是概率阈值限制
- 两者可同时使用，取交集
- 默认 top_k=0（不启用），仅使用 top_p 过滤

## sample_count（采样次数）

### 定义

对同一输入进行多次独立采样，最终取均值作为预测结果。

### 工作原理

在 `auto_regressive_inference` 中，输入数据会被复制 `sample_count` 份，并行执行采样，最后将多条路径的解码结果取平均。

| sample_count | 效果 | 适用场景 |
|-------------|------|---------|
| 1 | 单次采样 | 快速预测、回测 |
| 5 | 5次采样取均值 | 平衡速度与稳定性 |
| 10 | 10次采样取均值 | 概率预测、风险评估 |

### 实测数据

测试条件：SH600519，T=1.0，top_p=0.9

| sample_count | close 标准差 | 末值 |
|-------------|------------|------|
| 1 | 175.55 | 8644.33 |
| 5 | 142.11 | 8667.79 |
| 10 | 164.81 | 8624.59 |

sample_count 增大后，预测结果更平滑（标准差降低），但推理时间线性增加。

## 参数组合推荐

| 场景 | T | top_p | top_k | sample_count | 说明 |
|------|---|-------|-------|-------------|------|
| 快速回测 | 0.01 | 0.9 | 0 | 1 | 近似贪心，结果可复现 |
| 日常预测 | 1.0 | 0.9 | 0 | 1 | 标准采样，忠实模型分布 |
| 稳健预测 | 1.0 | 0.9 | 0 | 5 | 多次采样取均值，降低随机性 |
| 风险评估 | 1.0 | 0.9 | 0 | 10 | 概率预测，观察路径分布 |
| 保守预测 | 0.5 | 0.9 | 0 | 1 | 降低随机性，偏向高概率路径 |
| 探索性分析 | 1.5 | 0.9 | 0 | 1 | 增加随机性，探索更多可能路径 |
