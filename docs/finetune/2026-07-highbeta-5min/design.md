# 方案设计 - 高贝塔 5min 微调

> 本文档记录方案设计层面的决策:**为什么这么设计**、**CV 怎么切**、**数据怎么处理**。
> 实施细节见 [devlog.md](devlog.md)。

---

## TL;DR

- 预测频率:**5min**(由 1min 聚合),预测**次日全天 48 根**走势
- 股池:**严格用历史股池快照**(每日实际成分,贴合部署)
- 时间切分:**4 折扩张式时间序列 CV + 最终全量模型**(数据仅 2.5 年,不做每日滚动)
- 代码路径:基于 `finetune/`(qlib 多股票)扩展,不用 `finetune_csv/`(单股票)

---

## 1. 核心决策(均已确认)

| 决策点 | 选择 | 理由 |
|---|---|---|
| 预测频率 | 5min K 线(由 1min 聚合) | 用户指定 |
| 股池范围 | 严格用历史股池 `universe_snapshots.csv` | 贴合实际部署 |
| 训练窗口 | lookback=240(5 交易日)→ predict=48(次日全天),允许跨日 | 训练/推理结构一致 |
| 时间切分 | 4 折扩张式时间序列 CV + 最终全量模型 | 数据仅 2.5 年,不做每日滚动 |
| 代码路径 | 基于 `finetune/`(qlib 路径)扩展 | 原生支持多股票 DDP,finetune_csv 只支持单股票 |

| 数据 | 路径 | 说明 |

| 黑名单 | `SH600599 / SH600636 / SH600696 / SH688287` | 1min factor 退化(数据口径错误)|

### ⚠️ 重要发现:股池并集 = 5114 只(远超预估)

预估 500-800 只,实际**并集 5114 只**,接近全 A 股。原因:
- 高贝塔股池每日 100 只,但**换手率极高**:相邻日重叠仅 5 只(新进 95 / 退出 95)
- "高贝塔"是个**动态属性**,几乎所有 A 股都曾在某个时点进入过高贝塔池
- 这解释了 `universe_snapshots.csv` 有 609 日 × 100 = 6 万行,但并集 5114 只

**影响**:preprocess 不能无脑拉 5114 只全量 1min(数据量爆炸),改为按 CV fold 时段只拉该时段股池并集。

## 3. CV 切分设计(4 折 × 验证 20 日)

### 切分示意图

```
交易日轴  2024-01-02(第1日) ─────────────────── 2026-07-10(第609日)

折叠0: [训练469日 ████████][验证20日▓▓]          val=[第470-489日]
折叠1: [训练489日 ████████████][验证20日▓▓]      val=[第490-509日]
折叠2: [训练509日 ████████████████][验证20日▓▓]  val=[第510-529日]
折叠3: [训练529日 ████████████████████][验证20日▓▓] val=[第590-609日]
                                                          ↑最近行情
最终:  [训练609日 全量 ████████████████████████████████] → 上线
```

- 4 个验证段共 80 日,中间无间隔(连续滚动)
- 训练段**扩张式递增**(每折训练数据越来越多)
- 每折 pickle 路径:`finetune/data/highbeta_5min/fold{0-3}/{train,val}_5min.pkl`

### 实际切分边界(扩张式,无未来泄露)

```
折叠0: 训练[~2026-03-13] | 验证[2026-03-16~2026-04-13]  ✅
折叠1: 训练[~2026-04-13] | 验证[2026-04-14~2026-05-14]  ✅
折叠2: 训练[~2026-05-14] | 验证[2026-05-15~2026-06-11]  ✅
折叠3: 训练[~2026-06-11] | 验证[2026-06-12~2026-07-10]  ✅ ← 最近
最终:  训练[全量 2024-01-02~2026-07-10]
```

每折训练终点 < 验证起点,**严格无未来数据泄露**。

### 为什么用扩张式而非滚动式?

- 数据仅 2.5 年(609 交易日),滚动式每折训练数据太少
- 扩张式训练段递增,既保证训练量又能验证不同市场阶段
- 最终全量模型用所有数据训练,验证复用 fold3 的最近行情段

## 4. 窗口设计

```
样本总长 = lookback + predict + 1 = 240 + 48 + 1 = 289
                  ↑                ↑          ↑
                  5 交易日历史      次日全天    next-token 平移用
```

- **lookback=240**(5 交易日 × 48 根/天):用前 5 交易日全天数据
- **predict=48**(次日全天):预测次日 48 根 5min
- **允许跨日**:序列保留隔夜缺口,不截断
- 受 Kronos-base `max_context=512` 限制,289 < 512 ✅

### 特征列(6 维)

```
['open', 'high', 'low', 'close', 'vol', 'amt']
```

- qlib bin 无原生 amount,用 `amt = close * volume` 派生(后复权口径)
- ⚠️ 不能用 `amt = vwap * volume`(qlib vwap 不复权,close 后复权,口径混乱)

### 时间特征(5 维,从 5min datetime 派生)

```
['minute', 'hour', 'weekday', 'day', 'month']
```

## 5. 归一化策略(防泄露)

`dataset.py` 中:
- **仅用 lookback 段算 mean/std**,不用 predict 段(防未来泄露)
- 窗口 z-score 归一化
- `clip=5.0` 裁剪异常值

这与 config 无关,沿用原 `QlibDataset` 逻辑。

## 6. 为什么不单独训练 tokenizer?

本方案 **tokenizer 用预训练的,只训练 predictor**。理由:
- 训练 tokenizer 需要大量数据 + 时间,首版优先验证 predictor 微调是否有效
- 预训练 tokenizer 在全球 45+ 交易所训练,码本应有一定泛化性

**这是回测不赚钱的疑点之一**——5min 分布可能与 tokenizer 训练数据不一致,导致量化失真。后续改进方向已记录。

## 7. 数据规模估算

- 5114 只股票,52 批(100 只/批),预计 ~35 分钟
- 产物:4 折 × {train ~7GB, val ~0.3GB} + full ~9GB,共约 30GB

```
5038 只股票(5114 只中有 76 只无 1min 数据被跳过)
总 5min K 线:144,195,649 根
耗时:1633 秒(27 分钟)

各折:
  fold0: train 5015 只 / val 5022 只 [2026-03-16~04-13]
  fold1: train 5023 只 / val 5029 只 [2026-04-14~05-14]
  fold2: train 5030 只 / val 5029 只 [2026-05-15~06-11]
  fold3: train 5036 只 / val 5035 只 [2026-06-12~07-10]
  full:  5038 只 [全量]

产物大小:每折 train ~3.8-4.3GB,val ~150MB
```
