# 05 — 我们学到什么

> 目标:总结两次失败实验的真正价值,以及对后续工作的建议。
>
> 失败的实验如果教训清晰,比一次偶然的成功更有价值。

---

## 核心结论(三句话)

1. **Kronos 原生架构不适合 A 股高贝塔选股**:它学会了预测 K 线形态,但学不会横截面选股 alpha
2. **数据量和评估方法不是瓶颈**:实验 2 把数据增加 7 倍、评估方法改对,结果没变好
3. **正确的评估方法是最有价值的产出**:超额 RankIC 让我们看穿了"loss 低却亏钱"的真相

---

## 学到的东西(按重要度排序)

### 1. Val Loss 低 ≠ 能赚钱(最重要)

这是两次实验最大的认知收获。

```
Val Loss 衡量: K 线 token 重建误差(形态层面准不准)
选股需要:     横截面排序能力(谁比谁强)
              ↑
              这两个是不同的任务
```

**对后续工作的启示**:做量化选股实验,**主指标必须是 RankIC**(或 IC、IR),不能是 Val Loss。loss 只能当"模型健康度"的辅助参考。

### 2. 累计收益会骗人

实验 2 的 fold1/fold2 累计收益 +16%,但 RankIC 为负 —— 这是市场 beta 或运气,不是 alpha。

**对后续工作的启示**:报告策略表现时,**必须同时给累计收益和 RankIC**。只给累计收益的回测不可信。

### 3. 要看所有折,不只看最优模型

如果只看实验 2 的 full 模型(RankIC 0.034),会得出"基本通过门禁"的乐观结论。但看 4 个单折(全部 ≤ 0),真相是"模型没学到稳定 alpha"。

**对后续工作的启示**:用 k 折 CV 时,**所有折都要达标**才算通过。只挑最好的一折报告,是自欺欺人。

### 4. sample_count 影响评估

sample_count=20 让 RankIC 高估到 0.079,sample_count=1 只有 0.034。

**对后续工作的启示**:评估时用 sample_count=1(最保守),生产部署时再调高。或者多值对照(1/5/20)。

### 5. 数据量不能解决根本问题

实验 1(4 月数据)失败 → 实验 2(2.5 年数据)还是失败。增加 7 倍数据,RankIC 没改善。

**对后续工作的启示**:如果方法本身不对,堆数据没用。先在小数据上验证"方法是否成立",再扩大数据。

### 6. Kronos 的能力边界

经过两次实验,我们能确定地说:

| 任务 | Kronos 是否适用 |
|---|---|
| 单标的走势预测(如 BTC) | ✅ 可能(Demo 仓库验证过) |
| 合成 K 线生成 | ✅ 可能(论文报告保真度提升 22%)|
| 波动率预测 | ✅ 可能(论文报告 MAE 降 9%)|
| **A 股高贝塔选股** | ❌ **不适用**(本实验证明)|

为什么?选股需要**横截面比较**(100 只里挑 10 只),而 Kronos 是**单序列自回归**(一次预测一只)。它的架构里没有"比较多个标的"的机制。

## 对后续工作的建议

### 路径 A:放弃 Kronos 选股,转向 LGBM(推荐)

本项目作者的 `qlib_ifind_beta` 项目用 **LGBM + 18 个手工因子**,在同一高贝塔股池上:

```
IC = 0.067    ← 有效
超额累计 = +177%    ← 远优于 Kronos 两次实验
```

LGBM 之所以有效,是因为:
- 它直接优化"因子 → 未来收益"的映射(监督学习)
- 不经过"预测 K 线 token"这个中间步骤
- 横截面比较是它的天然能力(每只股票打分,排序)

**如果你真的要做高贝塔选股,走这条路,不要在 Kronos 上继续投入。**

### 路径 B:改造 Kronos 架构(高风险)

如果坚持用 Kronos,需要架构层面的改造:

1. **加 Ranking Head**:在 predictor 后面加一个"排序头",直接输出股票排名(而非 K 线 token)。这偏离 Kronos 原生设计,等于半个新模型
2. **加横截面注意力**:让模型能同时看多只股票(如同一行业的全部成分股),学习相对强弱

这些改造成本高,且没有论文验证过,风险大。

### 路径 C:换任务(用 Kronos 做它擅长的事)

Kronos 可能在这些任务上有效(未验证):

- **单标的价格预测**:如预测某只股票/指数的未来 N 日走势(不做横截面选股)
- **波动率预测**:用于期权定价或风险管理
- **合成数据生成**:生成模拟 K 线,做数据增强
- **异常检测**:识别 K 线形态异常(如潜在操纵)

这些任务不需要"横截面比较",更契合 Kronos 的单序列架构。

## 复用的工程资产

虽然选股失败,这两次实验沉淀了大量可复用的工程代码:

| 资产 | 位置 | 用途 |
|---|---|---|

| DDP + sglang 共存 | `run_daily.sh` | 在 sglang 占卡时跑训练 |

这些代码下次做任何量化实验都能直接用。

## 一句话给后来者

>
> 但 Kronos 不是没用 —— **实验 3 证明,当"特征提取器"注入 LGBM,它能提供与动量因子互补的反转信号,RankIC +6.4%**。详见 [07 实验 3 突破](07-breakthrough-features.md)。
>
> 如果你想学 Kronos 的架构思想(tokenize + 自回归),这份报告和 [架构文档](../architecture/kronos-overview.md) 是很好的教材。
>
> 如果你想做的是单标的预测或合成数据,Kronos 值得一试,但本报告的评估方法(RankIC)不适用,请参考论文的指标。

## 🔁 重要更新:实验 3 找到了正确用法(2026-07-21)

本篇以上内容写于实验 1、2 失败后,当时我们建议"别用 Kronos 做选股"。**这个结论现在需要修正**:

实验 3 换了思路 —— 不让 Kronos 端到端选股,让它当**特征提取器**,产出 8 个特征注入 LGBM。结果 OOS RankIC +6.4%,首次验证有效。

**修正后的结论**:
- ❌ 端到端选股:不推荐(实验 1、2 证明)
- ✅ 特征提取器 + LGBM:推荐(实验 3 证明,**必须微调**)

这印证了本篇的核心教训之一:**评估指标用对了,才能得出正确结论**。前两次的失败不是"Kronos 没用",而是"用法错了"。详见 [07 实验 3 突破](07-breakthrough-features.md)。

## 风险提示

1. 本结论基于**高贝塔股池 + A 股 + 日频/5min** 的具体设置。其他市场/股池/频率可能有不同结论
2. 实验 1、2 的失败结论限于"端到端选股",**不代表 Kronos 对选股完全无用**(实验 3 已证伪)
3. 实验 3 的 RankIC +6.4% 是 OOS 3 个月结果,需更长 OOS 验证
4. **不构成投资建议**。所有回测均为历史数据,过去表现不预示未来
