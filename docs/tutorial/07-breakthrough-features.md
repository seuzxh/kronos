# 07 — 实验 3 突破:从"端到端选股失败"到"特征提取器成功"

> 这是整个项目最重要的转折点。前两次实验失败后,我们差点判定"Kronos 对 A 股选股无用"。实验 3 换了个思路,**首次验证了 Kronos 在 A 股选股上的有效用法**。
>
> 读懂这篇,你就懂了"Foundation Model 怎么用才对"。

---

## TL;DR

| 维度 | 实验 1、2(失败) | 实验 3(成功) |
|---|---|---|
| **Kronos 的角色** | 端到端选股器 | **特征提取器** |
| **用法** | Kronos 预测涨跌 → 直接选 Top 10 | Kronos 预测 → 提取 8 特征 → LGBM 排序 |
| **结果** | RankIC ≈ 0 | **RankIC +6.4%** ✅ |
| **失败/成功根因** | 架构-任务错配 | 各司其职,优势互补 |

**核心洞察**:Kronos 不是"选股器",是"形态理解器"。别让它做不擅长的(横截面排序),让它做擅长的(形态特征),再交给 LGBM 做排序。

---

## 1. 失败的教训:为什么端到端选股不行

回顾 [03 怎么验证](03-how-we-evaluated.md):Kronos 的训练目标是"预测下一根 K 线 token",这让它在**形态层面**很强,但**横截面排序**能力几乎为零。

```
选股需要: 比较 100 只股票谁更强  ← Kronos 不会
Kronos 会: 续写单条 K 线         ← 用错地方了
```

实验 1、2 都是让 Kronos 端到端做"预测涨幅 → 选 Top 10",结果 RankIC ≈ 0。**这是架构限制,不是数据量或调参问题**。

---

## 2. 关键思路转换:Foundation Model 的标准用法

实验 3 的灵感来自一个观察:**BERT/GPT 在 NLP 领域,也不是端到端做下游任务的**。

```
NLP 的标准用法:
  BERT(预训练) → 提取词向量 → 喂给具体任务模型(分类/NER/...)

实验 3 的做法:
  Kronos(微调) → 提取 K 线形态特征 → 喂给 LGBM(横截面排序)
```

这是 Foundation Model 的**标准玩法**:预训练模型当特征提取器,下游任务用专门的模型。我们前两次硬让 Kronos 端到端选股,其实是用错了。

---

## 3. 实验 3 的具体设计

### 3.1 尺度对齐(关键)

LGBM 的决策是"T 日 9:41 买入、T+1 收盘卖出"(horizon ≈ 1.5 天)。Kronos 的输入输出必须**与这个 horizon 对齐**:

```
Kronos 输入: 过去 5 交易日的 5min K 线(240 根)
Kronos 输出: 预测 T 日全天 5min K 线(48 根)
              ↑ 覆盖 LGBM label 的前半段
```

**严格防泄露**:特征写 T 日,信息截止 T-1 收盘。T 日开盘前的所有决策都基于完整可得信息。

> 💡 这个设计修正了之前一个错误:实验 2 用 240 天日线历史,与 1.5 天 label 严重错配。实验 3 用 5 天 5min 历史,完美对齐。

### 3.2 8 个特征(不只看涨跌)

从 Kronos 预测的 48 根 5min 路径提取 8 个特征:

| 特征 | 含义 |
|---|---|
| `ret_intraday` | 预测 T 日累计收益 |
| `high_ratio` / `low_ratio` | 预测日内最高涨幅 / 最大跌幅 |
| `range` | 预测日内振幅 |
| `close_pos` | 预测收盘相对位置 |
| `morning_ret` / `afternoon_ret` | 预测上午/下午收益 |
| `uncertainty` | 多次采样间的标准差(模型信心度)|

**关键设计**:不只提取"预测涨跌"(那只是 1 个特征),而是从预测路径中提取多维信息(波动、形态、信心度)。这让 Kronos 的形态理解能力真正发挥作用。

### 3.3 多采样机制

Kronos 的自回归预测支持多次采样。官方 `predict()` 方法对多次采样取**平均**,丢失了路径间差异。

实验 3 改成:拿到 **5 条独立采样路径**,算前 7 个特征的均值,`uncertainty` 用路径间标准差。这样多了一个**模型信心度**信号。

## 4. 三跑 Ablation 结果

| 跑 | 特征数 | Kronos 来源 | IC | RankIC | 判定 |
|---|:---:|---|:---:|:---:|:---:|
| **A baseline** | 18 | 无 | 0.0548 | 0.0612 | 对照 |
| **B +base** | 26 | Kronos-base(zero-shot)| 0.0329 | 0.0439 | ❌ -28% |
| **C +finetune** | 26 | highbeta_5min 微调 | 0.0491 | **0.0651** | ✅ **+6.4%** |

### 4.1 C 跑成功:RankIC 提升 6.4%

C 跑的 OOS RankIC 从 0.0612 提升到 0.0651,达到预设的成功门槛(0.0612 × 1.05 = 0.0643)。

### 4.2 B 跑失败:base 模型有看跌偏差

预训练的 Kronos-base **没在 A 股训练过**,99% 的样本预测收益 < +1.22%,有强烈的系统性看跌偏差。这个偏差注入 LGBM 后**误导了原本有效的 18 因子**,RankIC 反而下降 28%。

### 4.3 微调校准了偏差

finetune 版在高贝塔股池上训练过,校准了 A 股特有的偏差:

| 特征 | base mean | finetune mean | 说明 |
|---|:---:|:---:|---|
| `ret_intraday` | -2.90% | **-0.21%** | 校准看跌偏差 |
| `close_pos` | 0.28 | **0.45** | 接近 0.5 中性 |

**这是微调的真正价值** —— 不是让预测"更准",而是校准市场特有的偏差。

---

## 5. 最有趣的发现:Kronos 是反转信号

单特征 RankIC 分析显示,Kronos 特征本质是**反转信号**:

| 特征 | RankIC | 含义 |
|---|:---:|---|
| `range` | **-0.054** | 预测振幅大 → 未来收益**差**(最强)|
| `uncertainty` | -0.037 | 不确定性高 → 未来差 |
| `low_ratio` | +0.037 | 预测跌得多 → 未来反而**好** |
| `high_ratio` | -0.035 | 预测涨得多 → 未来差 |

**Kronos 预测的"看涨"方向与实际相反!** 这不是 bug,而是真实的**反转效应** —— 短期被预测要涨的股票,往往已经涨过头,接下来会回落。

### 为什么这与 LGBM 互补

LGBM 的 18 因子主要是**动量信号**(startup_mom、accel 等,逻辑是"涨的继续涨")。Kronos 提供**反转信号**,两者互补:

```
现有因子: "最近在涨,继续买"      (动量,追逐趋势)
Kronos:   "预测要涨,但其实会跌"  (反转,止盈信号)
          → 结合:动量 + 拐点检测
```

这解释了为什么加入 Kronos 后 RankIC 提升 —— 它提供了原 18 因子**缺失的反转维度**。

## 6. IC 下降但 RankIC 上升(重要 nuance)

C 跑有个反直觉现象:
- **IC(Pearson 线性)下降 10%**:0.0548 → 0.0491
- **RankIC(Spearman 排序)上升 6.4%**:0.0612 → 0.0651

**为什么这是好事**:

| 指标 | 衡量什么 | 选股关心吗 |
|---|---|:---:|
| IC | 预测值与实际的**线性相关** | ❌ 不关心 |
| RankIC | 预测排序与实际排序的**相关性** | ✅ 选股只关心"买前 10 名"|

IC 下降说明 Kronos 特征引入了异常值,扰动线性相关。但 RankIC 上升说明**排序变好了**,而选股只关心排序。**用 RankIC 评估选股,是 [03 怎么验证](03-how-we-evaluated.md) 教给我们的最重要一课**。

## 7. 工程亮点:6 卡并行

实验 3 的特征提取用了 **6 卡数据并行**,把单卡 ~8 小时压到 **~100 分钟**(快 4.8 倍)。

```
598 个决策日 → 拆成 6 份
6 个 worker 进程,各绑一张 GPU(GPU 1-6)
各处理 100 天,写独立 parquet
最后单进程合并写 bin(避免文件竞争)
```

**为什么能这么做**:sglang 虽然占了 8 张卡的内存(83GB/卡),但**计算利用率是 0%**。Kronos 推理只需 ~3GB,剩余 13GB 完全够用。

这是个有用的经验:**看 GPU 能不能用,不能只看内存占用,要看计算利用率**。

## 8. 这次实验学到了什么

### 8.1 关于 Kronos

1. **端到端选股不行,特征提取器路线有效** —— 这是 Foundation Model 的标准用法
2. **必须微调** —— 预训练 base 有市场偏差,直接用反而有害
3. **Kronos 的价值在"形态理解",不在"预测准确"** —— 它能提取人手工难写的反转特征
4. **微调的真正作用是校准偏差**,不是提升预测精度

### 8.2 关于量化方法论

1. **评估必须用 RankIC**,不能看 IC 或 Val Loss(实验 1、2 的核心教训)
2. **IC 和 RankIC 可能背离** —— 选股看 RankIC
3. **互补性比单特征强弱重要** —— Kronos 单特征 RankIC 只 -0.054(弱),但与动量因子互补,集成后提升整体
4. **特征工程 > 模型堆砌** —— 同一个 Kronos,端到端用失败,当特征提取器用成功

### 8.3 关于工程

1. **GPU 多卡并行能省大量时间** —— 关键是判断"卡是否真的在用"
2. **复用预处理产物** —— 加载 5min pickle 比重新聚合快 400 倍
3. **防泄露要严格** —— 特征写 T 日,信息截止 T-1,逐日滚动

## 9. 局限性与后续

### 9.1 这次结果的局限

1. **OOS 样本短**:test 段只有 2026-04~07 三个月,需更长 OOS 验证
2. **回测未完整**:三跑的回测都卡在 qlib exchange(环境问题,与特征无关),超额收益待补
3. **RankIC +6.4% 是弱提升**:单看不够强,需结合回测确认是否实盘可用

### 9.2 后续优化方向

1. **特征筛选**:只用 `range`、`uncertainty`、`low_ratio` 三个强信号
2. **Winsorize 异常值**:改善 IC(虽然 RankIC 已达标)
3. **特征交互**:Kronos 反转 × 现有动量的交互项,可能捕捉"动量到反转的拐点"
4. **滚动重训**:Kronos 特征依赖微调,生产用必须定期重训(参考 LGBM 的 rolling retrain)

---

## 10. 最终结论

> **Kronos 对 A 股选股不是"有用"或"没用",而是"看怎么用"。**
>
> - ❌ 端到端选股:架构-任务错配,必败(实验 1、2)
> - ✅ 特征提取器 + LGBM:优势互补,有效(实验 3)
>
> 关键前提:**必须微调**(base 版有偏差,会拖累 LGBM)。

这个结论比"成功/失败"二元对立更 nuanced,也更接近真实世界的复杂性。前两次的"失败"不是白费 —— 正是它们让我们理解了 Kronos 的能力边界,才找到了实验 3 的正确用法。

**失败是成功之母,但前提是诚实归因、深入理解、敢于换思路。**
