## 3. 为什么模型不赚钱? 深度分析

### 根本原因: 模型没有学到"选股 alpha", 只学到了"5min形态平均"

```
Val Loss 2.19 (低) ← 模型学会了"预测5min K线形态"
     ≠
选股 alpha      ← 需要的是"区分哪些股票明天涨更多"
```

### 证据链

1. **胜率40% < 50%**: 选出的top-10表现不如随机, 说明排序方向有误
2. **v1 fold1 假盈利**: 旧信号bug下偶然盈利, 修复后变亏损, 证明非真实alpha
3. **4折全部亏损**: 无一例外, 不是特定时段问题, 是模型能力问题

### 为什么 Val Loss 低却不赚钱?

- Val Loss 衡量"5min K线的token重建误差", 是**形态层面**的准确度
- 选股需要**横截面排序能力**(今天100只里哪些明天涨最多), 这是不同的任务
- 模型可能把所有股票都预测成"均值回归"的相似形态, 失去区分度

---

## 4. 高贝塔股池的特殊难度

这个任务本身极其困难:
1. **高贝塔股波动剧烈**: 信噪比极低, 可预测性本来就差
2. **每日换手84%**: 几乎是全新的股票池, 历史规律不延续
3. **5min级噪声**: 分钟数据噪声远大于日K
4. **持仓1天周期**: 短周期更难预测

参考: 你的 qlib_ifind_beta 项目用 LGBM + 18个手工因子, IC也仅0.067。
Kronos 直接从5min K线预测, 没有手工因子, 难度更大。

---

## 5. 改进方向 (现实评估)

### 🔴 可能需要根本性改变 (成本高)

1. **改预测目标**: 当前预测5min K线(token), 改为直接预测"次日涨跌幅排名"(IC任务)
   - 但这偏离 Kronos 架构, 等于换模型
2. **加入横截面信息**: 当前每只股票独立预测, 无市场/行业对比
   - 改为 ranking loss 或加入市场特征

### 🟡 值得尝试 (中成本)

3. **微调 tokenizer**: 当前用预训练的, 可能在5min分布上失真
4. **融合手工因子**: 把 qlib_ifind_beta 的18个分钟因子作为额外特征输入
5. **更长持仓**: 预测准的可能是趋势而非日内, 试T+3/T+5
6. **不同 top-K**: top-10太集中, 试top-30或加分位持仓

### 🟢 快速验证 (低成本)

7. **降低 sample_count**: 当前20次采样取均值, 可能过度平滑, 试sample=1
8. **调推理温度 T**: 当前T=1.0, 试T=0.1(更确定)或T=5(更多样)
9. **多信号组合**: close+high+low综合打分, 非仅close

---

## 6. 结论与建议

### 当前模型: ❌ 不可直接用于交易

4折稳定亏损(-9.36%/折), 胜率40%, 夏普-3.79。

### 建议路径

**短期(验证模型上限)**:
- 先试改进方向7-9(推理参数调优), 快速看是否有改善空间
- 若仍亏损, 说明当前架构不适用此任务

**中期(根本改进)**:
- 方向3-6(微调tokenizer + 融合因子 + 改持仓), 需要重新训练/回测

**长期(架构变更)**:
- 方向1-2(改预测目标到排名), 这其实是 qlib_ifind_beta 的 LGBM 路线

### 客观看待

这次实验的价值不在于"做出赚钱策略", 而在于:
1. ✅ 完整验证了 Kronos 在5min高贝塔股池的能力边界
2. ✅ 证明了"Val Loss低 ≠ 能赚钱"
3. ✅ 为后续改进提供了清晰的基线和方向
4. ✅ 对比基准: 你的LGBM champion(IC 0.067, 超额+177%)远优于当前Kronos方案
